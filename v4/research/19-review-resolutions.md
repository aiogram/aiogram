# 19 — Resolutions of the independent review (codex-review.md)

[codex-review.md](codex-review.md) raised R01–R30. Four verification passes checked every finding against the 3.x
code (inline probes with fake tokens), upstream docs and these pages. Almost all findings were confirmed.

**Corrections to the review:**
- `model_extra` returns `{}`, never `None`.
- `model_dump_json()` also changes its default *keys*, not only the `by_alias=False` case.
- The PyMongo `update_data` already returns an atomic post-update snapshot.
- Only 3 of the 12 undiscriminated unions are ever decoded.
- 3.x polling admission is already bounded.
- Pickling a bound object already fails in 3.x.

**New issues the review missed:**
- Returned methods are encoded after the i18n locale context exits.
- `setup_application()` can't install an access logger (aiohttp accepts `access_log_class` only in `run_app` /
  `AppRunner`).
- `-W error::aiogram.AiogramDeprecationWarning` is rejected by CPython ("invalid module name").
- `inspect` rejects a `text_signature` containing `Default(...)`.
- 3.x leaked the token through download errors: ANT-2026-4GL80S7S, a raw `ClientResponseError` containing
  `/file/bot<token>/`. Fixed in 3.33.0 ([GHSA-52j5-qrwv-2vf2](https://github.com/aiogram/aiogram/security/advisories/GHSA-52j5-qrwv-2vf2)).

These resolutions are folded into the other pages (A-02), which now state the current contract directly. This page
stays as the history and index of the review decisions; the planning decisions that revise some of them are PD-01..PD-34
in the [plans README §1](../plans/README.md), marked "revised by PD-xx" below.

## 1. Owner decisions (D103–D121)

| # | Finding | Decision |
|---|---|---|
| **D103** | R02 | **Independent bound views.** `obj.as_(bot)` returns a **new view** over the same immutable data, and children of a view inherit its bot. There is no shared mutable context, no atomics and nothing redirects another holder's shortcuts. Dispatcher remounting creates a new root view in O(1). Identity (D53) holds within one view and for unbound construction, not across `as_()`. Code that uses the return value (`m = m.as_(bot)`, all generated shortcuts, the docs) keeps working. A bare `x.as_(bot)` statement no longer rebinds `x`; the migration checker flags it. README breaking change 22. Replaces the `ArcSwapOption` Ctx in 01 §3.2 |
| **D104** | R01 | **No pre-committed fallback.** If the spike gate fails, the model layer is redesigned from scratch. Every decision that assumes Rust-native types is **conditional on the gate**: D4, D11, D14, D53 (mechanism), D83–D87, D91–D95, D102, D103 |
| **D105** | R06 | **Unknown fields readable as attributes, deprecated.** On an attribute miss, `__getattr__` returns the unknown field from raw data, with a one-time `AiogramDeprecationWarning` pointing to `.raw`. This lasts one D71 window, then `AttributeError`. There is no hot-path cost, and `F.new_field` keeps matching during the window |
| **D106** | R06 | **Collection fields are cached tuples** (`entities`, `photo`, `getUpdates` result, keyboard rows): identity-stable, immutable, and hashable when their items are. README breaking change 23: `== [..]` comparisons and `.append` stop working. The checker flags list comparisons where it can |
| **D107** | R07 | **The nearest decoded union absorbs malformed data.** A malformed member of a *decoded* union becomes `Unknown…` carrying `.decode_error` and its raw value, and the rest of the update stays usable. Failures outside any union fall to the per-update `UpdateDecodeError` (10 Layer 2). `Unknown` variants exist only for unions that are decoded (MaybeInaccessibleMessage, ChatMember results, MenuButton results, every tagged union). Request-only unions with primitive members (ChatId, DateTime, InputFile, …) get none. Revises D85: tag or overlay predicate, otherwise `Unknown`; the **declaration-order fallback is dropped** |
| **D108** | R05 | **Raw and value semantics.** `.raw` returns a fresh `dict` on every access. `.raw_json` returns the exact received bytes for wire objects, and canonical `to_json()` bytes for constructed or replaced objects. `replace()` drops the original bytes, so pickle and raw never show stale data. Equality compares class and data and **ignores the bot binding** (3.x compared bots by token, so this is a minor change). An object is **hashable only if all its fields are** (excluding raw and binding); the 3.x behaviour was `TypeError` on list fields, and with D106 tuples most objects become hashable. Revises the hash wording of D84 |
| **D109** | R08 | **Overlay rename rule for name collisions.** The overlay maps colliding wire names to Python names: `bot` → `bot_user` on ManagedBotCreated / ManagedBotUpdated, as in 3.x. Reserved names are **exact names**, not prefixes: `bot`, `raw`, `raw_json`, `to_json`, `to_dict`, `from_json`, `from_dict`, `replace`, `as_`, the `model_*` aliases. `UniqueGiftColors.model_custom_emoji_id` stays legal. Butcher `check` fails on a new collision until a rename is configured (refines D92) |
| **D110** | R14 | **D28 kept, plus an escape hatch and a warning.** Isolation stays on by default. `async with state.release_isolation():` lets a handler wait for a later update of the same key. A warning fires when a key's lock is held longer than `isolation_warn_after` (default 30 s). Breaking change 15 now names the incompatible patterns: "ask and wait" helpers and re-entrant `feed_update` for the same key |
| **D111** | R10 | **Flatten everything (documented break).** The compiled plan for a matched candidate wraps only the outer middlewares of the routers **on its path**. Outer middlewares of routers that hold no matching candidate are **skipped**, even though in 3.x they run for every update reaching them. Routing keys are computed once per update, so an outer middleware that replaces the event doesn't change routing. Continuation-called-twice and short-circuit still work on the path. README breaking change 24 |
| **D112** | R17 | **Providers always see the exception.** The exception that escaped the handler chain is recorded and thrown into every yield-provider (`athrow` / `throw`) regardless of later handling by `errors` handlers, so transactions roll back (FastAPI semantics). A provider that swallows it doesn't suppress it. Teardown errors go **only** to `dp.runtime_errors` (phase `TEARDOWN`) and are never re-raised from `feed_update`. Teardown completes before a source marks the update done. `ErrorPhase` gains `DEPENDENCY` and `TEARDOWN`. *Revised by PD-04: teardown runs inside the isolation scope, after `errors` handlers and before the FSM isolation lock is released (03 §5)* |
| **D113** | R15 | **`RedisHashStorage` is deferred** to a 4.x minor, and so is its migration tooling. 4.0 ships the legacy `RedisStorage` layout: pipelined state+data read in 1 RTT, no Lua, user codec hooks unchanged, atomicity through isolation (D28), and cluster-safe because there are no multi-key scripts. Revises D29. Mongo: data keys containing `.`, a leading `$` or the empty string are rejected with a clear error (dotted-path bug in 3.x) |
| **D114** | R11 | **Per-Runner routing snapshots; nothing is frozen.** At start, each Runner compiles an immutable snapshot of the routing table, chains, copied flags, filters, Depends plans and the scene registry. Dispatchers and routers stay ordinary mutable objects. Sharing across Runners and dispatchers is safe by construction, so no leases are needed. Changes after start apply **on restart or `runner.refresh()`**, and a one-time warning fires when someone mutates a graph that a running snapshot references. `dp.feed_update()` without a Runner compiles and caches a snapshot keyed by a topology epoch (recompiled after any change). D56's diamond check runs at snapshot compile. Replaces D19's "raise while running". The snapshot captures structure, not object state: filter and middleware instances are shared, and their thread safety is the user's. README breaking change 4 rewritten |
| **D115** | R16 | **Typed FSM patches.** `await state.update_data(OrderForm, qty=2)` validates each field and needs no full model. Passing a model instance merges **only explicitly set fields** (`exclude_unset`). Mutable defaults are copied per instance. `set_data(model)` writes the full model |
| **D116** | R20 | **Album aggregation deferred** out of 4.0 (D59 withdrawn). Per-handler buffering can't work behind the FSM lock, and the ingress designs are too risky for 4.0. To revisit as a Runner pre-dispatch stage |
| **D117** | R21 | **The i18n context is captured at return.** A method created inside an update, or returned from a handler, captures the current locale / i18n context. Encoding renders with it, which covers webhook inline replies and polling silent calls. Text **and** entities are rendered once per request snapshot, and retries reuse it. Explicit `entities` / `parse_mode` next to a lazy `Text` raise. *Revised by PD-07: the context is captured when a handler returns a method and when `bot(method)` is called; method constructors stay i18n-free (06 §3)* |
| **D118** | R24 | **Butcher provenance.** Each adapter's IR (`ir.html.json`, `ir.openapi.json`) is committed next to the merged IR, with a manifest: URLs, fetch time, sha256, tool and overlay versions, and an html-only flag. Raw source bundles are attached to releases as immutable assets. CI emits and checks **offline**; a scheduled online job re-extracts and diffs. The IR keeps direction-specific requiredness and constants even for merged twins (D18) |
| **D119** | R25 | **Release-blocking platform tiers.** **Tier 1** (blocks a release): CPython cp311–cp315 + cp314t/cp315t on manylinux x86_64/aarch64, musllinux x86_64/aarch64, macOS arm64/x86_64, Windows x64. **Best-effort** (never blocks): Windows arm64, i686/armv7l/ppc64le/s390x. PyPy is not supported at all (PD-35). An sdist is always published |
| **D120** | R27 | **3.x quick-win fixes.** Drop #6 (root-only binding) and #15 (sentinel → `object()`). Rework #2: fix the O(n²) in `add()`, and `export()` uses a per-button `model_copy` (63 → 8.7 µs, isolation kept). #1, #10, #18 and #21–22 carry compatibility notes, and each PR is measured against its own baseline |
| **D121** | review §9 | **Roadmap = milestones A–J** (README), each with its own exit gate. The full 4.0 feature set is kept, B (spike) is the binding go/no-go, and `4.0.0a1` is an alpha, not GA |

## 2. Applied without a separate decision (consistent with earlier decisions or pure fixes)

| Finding | Resolution |
|---|---|
| R03 | Wrapper caches build the child outside any lock and then publish it with an atomic `set`; the loser is dropped. A rare double allocation is allowed, and nothing ever blocks while Python runs. `PyOnceLock` only for process-wide globals. Re-entrant initialisation is never under a lock. GC: each wrapper holds its own `Py` references and reports each exactly once in `__traverse__` / `__clear__`. Subinterpreters are unsupported (PyO3 refuses import) |
| R04 | The cache has slots only for non-scalar fields that are present, not a fixed array of N. Each update's bytes are copied out of the batch buffer, so a retained child doesn't pin a 100-update buffer. The memory gate adds RSS of *accessed* trees, retained-child-from-batch cases and GC-on sustained runs |
| R06 | Alias contract (D91): `model_dump_json()` returns **`str`** (3.x return type) with wire names (D94). `model_extra` returns unknown fields only (`{}` when none). `model_dump(exclude_unset=True)` is supported through a per-field "present" bitset the decoder keeps anyway. `model_copy(update=…)` maps to `replace`, which validates (3.x didn't). Internal uses outside the alias subset (`dispatcher.py:280`, `aiohttp_server.py:176`) move to the native API |
| R09 | **3.x data scopes kept exactly (D38)**: update, router (copy at router entry), observer-trigger (shared, D38) and candidate-check (copied lazily at the first dict-returning filter, committed only on success). Removes the plan's "one data dict" wording |
| R12 | Runner API: `runner.feed()` **admits** (awaits capacity, then schedules); `runner.process()` runs inline and returns the reply (webhook). Webhook background mode has a pending cap (`max_pending`) beyond which it answers 5xx so Telegram redelivers. Only the main-thread Runner owns signals. "asyncio is thread-safe" corrected to per-thread loops (asyncio objects are not thread-safe) |
| R13 | D22 reworded: removal confirms **admitted** updates and doesn't replay them. A crash or a shutdown deadline may lose or replay work, so delivery stays **best-effort, not exactly-once**. `limit=1` results during removal are ignored and stay unconfirmed. A warning fires when `unknown_update` has handlers but `allowed_updates` is derived (Telegram won't deliver unknown types) |
| R18 | Webhook replies: JSON when the method has no files, **multipart** otherwise (the encoder already returns `JsonBody \| Multipart`). `deserialize_telegram_object` keeps its semantics: encoder output plus the method name, with defaults resolved and files extracted. `TelegramMethod.to_json()` is the model representation (unresolved `Default` omitted) and raises for `InputFile` values; the ready request is built only by the encoder. JSON hooks may return `str` or `bytes` |
| R19 | Retry safety comes from generated `idempotent` metadata plus overrides, not a `get*` prefix, and `getUpdates` is excluded (the Poller owns it). `RetryMiddleware` is outermost and `RateLimitMiddleware` charges **every attempt**, refunding tokens on cancel-while-waiting. `InputFile.replayable` (True for built-ins) gates retries of uploads. Lazy text is rendered once per request snapshot |
| R22 | **Never build token-bearing exception text**: aiohttp errors are wrapped `from None`, with the original kept on `.original`. 3.x fixed ANT-2026-4GL80S7S in 3.33.0 ([GHSA-52j5-qrwv-2vf2](https://github.com/aiogram/aiogram/security/advisories/GHSA-52j5-qrwv-2vf2)). A redaction filter goes on **every** `aiogram.*` logger, with a test that walks the logger dict; it rewrites only when a token matches, to keep Sentry grouping. A handler-level filter is exported for user handlers and attached to `aiohttp.access` / `uvicorn.access` by the CLI and the documented server setup (`setup_application` can't install an access logger; documented). Out of scope: error trackers that capture locals. *Revised by PD-14: the 4.x wrapping is D-03's; H owns only the log filters (15 §5)* |
| R23 | Tracers are called manually (`__enter__` / `__exit__`), exited in reverse order, with failures logged. Their return value is ignored and the original exception re-raised, so a tracer can never suppress or replace an app error. A `Span.set_attribute` protocol. Metric labels are bounded (no on-demand bot ids; `<lambda>` handlers get a stable registration-site name) |
| R25 | 08 rule 13 is "current rustc heuristic, verified by the B25 guard", not a guarantee. `-Ztime-passes` runs on a separate nightly job. The rustls / aarch64 note is deleted (no Rust networking). The largest-unit threshold is calibrated on real CI hardware |
| R26 | Differential harnesses carry **difference manifests**: each case is invariant, an approved difference (with a decision id and a narrow assertion) or newly supported. They add hand-curated wire fixtures and recorded traces (redacted, with provenance). The fake marks modelled versus synthesised methods |
| R28 | Checker findings are classed **definite / heuristic / manual checklist**, each with a confidence level and suppression. The codemod rewrites `obj.x = y` only as `obj = obj.replace(x=y)` on plain names and reports the rest. "Last 3.x minor" becomes a **named migration-baseline 3.x release**, with its warnings kept in every later 3.x release. The 4.0 ledger reset is an explicit exception to D71. Warning filters are installed only `if not sys.warnoptions`. The D72 recipe becomes pytest config / `warnings.filterwarnings` in code, because `-W` rejects the module path. Run before upgrading with `uvx --from 'aiogram[migrate]>=4' aiogram migrate check <path>` |
| R29 | The reference is built with **sphinx-autoapi** for everything, with `autoapi_file_patterns = ['*.pyi', '*.py']` so stubs win. Docs build from the docs dependency group with `--no-install-project`, so no Rust toolchain is needed. Fallback: a wheel-backed build |
| R30 | The final aiogram-cli release ships **no `aiogram` console script**; the docs mention `--force-reinstall aiogram` for broken upgrades. Click plugins load only when click is installed, and incompatible ones are reported. `delete_missing` covers the four fixed scopes × known languages, plus an explicit `managed=[(scope, lang), …]` list. `aiogram info` reports "installed optional packages", not requested extras. `run webhook` multi-bot needs an explicit `--bot TOKEN=PATH[:SECRET]` mapping |
| §8 | README D4 wording (generated from the resolved IR). "Small, documented breaks" → "a substantial, documented migration". `REJECTED` removed from 03's unchanged list. D31 / D32 described as cooperating mechanisms. The "one pass" decode wording fixed in 05. The 01 wrapper model is normative over 08's "no wrapper types". `text_signature` uses `...` for nonliteral defaults (`inspect` rejects `Default('parse_mode')` in a text signature); stubs carry the real defaults. The `TypedDict` example models availability correctly (separate outer and inner data types). Strict mode for known-schema corpus tests. B17 datetime / rounding / timeout rules moved into 01 / 05. All extras listed in the README. External package releases (aiogram_i18n, aiogram-cli) need owners in those repos |

## 3. Owner confirmations (2026-11-17)

Three defaults applied during propagation are confirmed:
1. The deprecated `model_dump_json()` alias returns **`str`** (3.x return type) with wire names (D94). `to_json()`
   returns `bytes`.
2. Typed DI (03 §5): `state`, `raw_state`, `event_router` and `handler` belong to the **inner**-middleware
   `TypedDict`, matching where 3.x sets them. Outer-middleware data types omit them.
3. Per-update byte copies out of the `getUpdates` batch buffer (R04) are **part of the design**, not conditional on
   the memory measurement.
