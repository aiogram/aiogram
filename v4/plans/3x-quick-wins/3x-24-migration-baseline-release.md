## Motivation

R28: the "last 3.x minor" can't carry the 4.0 warnings, because 3.x keeps getting Bot API bumps for 12 months after
GA (D73). Instead, a **named migration-baseline 3.x release** ships every warning, and every later 3.x release keeps
them. Users then upgrade to the baseline, fix the warnings, run `aiogram migrate check`, and move to 4.0.

## Scope

**In:**
- **Name the version early.** Record it in this plan's Notes and in [README.md](README.md) of this folder when 3x-20
  starts, so docs and 4.0 plans (I-22, J-04) can cite it. Proposed: the first 3.x minor after 3x-21..23 land.
- **Registry sync.** Copy the authoritative `registry.toml` from `dev-4.x` to `dev-3.x` (see A-11 Workflow notes).
  Every entry with a `warn_3x` site must have a 3.x implementation; 3x-20's sync test enforces this. Entries added on
  `dev-4.x` after the freeze ship in a later 3.x release, never silently.
- Fill `warn_3x.since` with the baseline version for every implemented entry.
- **"Preparing for 4.0" docs page** (`docs/migration/preparing_for_4.rst`):
  - the registry table generated by 3x-20's script;
  - how to see and escalate warnings: pytest `filterwarnings = ["error::aiogram.AiogramDeprecationWarning"]` or
    `warnings.filterwarnings("error", category=AiogramDeprecationWarning)` in code. `-W
    error::aiogram.AiogramDeprecationWarning` **does not work**, because CPython rejects the module path (R28);
  - **D100 / PD-02: positional API calls get no runtime warning.** `message.answer("hi")` and
    `bot.send_message(1, "hi")` must become keyword calls in 4.0. Only the checker reports them, and `aiogram migrate
    fix` rewrites them (I-18). State plainly that 3.x gives no warning for the largest-volume change;
  - the behaviour changes that no warning can catch, the manual checklist items from 18 §2: isolation on by default
    (D28/D110), sync filters inline (D34), routing snapshot (D114), compiled-rejector skip (breaking change 13), skipped
    outer middlewares (D111), error bubbling (D48), tuples (D106), `as_()` returns a new view (D103);
  - the 4.0 checker invocation once 4.0 betas exist: `uvx --from 'aiogram[migrate]>=4' aiogram migrate check <path>`;
  - the 3.x support policy: 12 months of full support plus 6 months security-only after 4.0.0 GA (D73). Exact dates
    come with J-04.
- Cut the release with the `aiogram-release` skill: version bump, towncrier build, tag.

**Out:**
- The 4.0 migration guide: J-02.
- The 4.x Deprecations page: I-12.

## Acceptance criteria

- The released wheel contains `registry.toml`. Every entry with `warn_3x.site != "none"` has `since` set and a
  passing trigger test.
- The page builds with no Sphinx warnings, and mentions the D100 no-warning gap, the `-W` limitation and the support
  window.
- The tag exists, and the release notes name it as the migration baseline.

## Rejected alternatives

| Alternative | Why rejected | Decision |
|---|---|---|
| Warnings only in the literal last 3.x minor | Bot API bumps continue after GA | R28 |
| Runtime warnings for positional calls | A per-call cost on every generated method | PD-02 (checker-only) |
| Cut before the 4.0 removal inventory is frozen | The baseline would miss removals | C-26 dependency |
