## Motivation

PD-01: the full D121 feature set, A to J including G and H, blocks 4.0 GA. The J gate needs two things: beta feedback
resolved, and **no unresolved P1 contract**.

A P1 resolution recorded in 19 is a paper decision. GA needs evidence that each decision is **implemented and tested**.
There are 21 P1 findings in the review: R01–R15, R17, R18, R20, R22, R24, R27. Some decisions were also withdrawn or
deferred, and GA must state them explicitly:
- D116 albums;
- D113 RedisHashStorage;
- abi3.

PD-06 moved single-bot sharding **into** 4.0.

## Scope

**In:**
- **An inventory table** `v4/plans/J-ga/inventory.md`. It is generated by a script over the plan files and the git log
  of `dev-4.x`, plus manual columns. It covers:
  - D1–D121 and PD-01 to PD-31, each with: implementing plan IDs, plan status, merged PR, test evidence (test module or
    acceptance criterion), and "deferred / withdrawn" with the decision id;
  - README breaking changes 1–24 plus the 11-removals items, each with: its registry id (PD-13), finding class,
    codemod coverage and guide page;
  - **each P1 finding R01–R30**, with the implementing test that proves the resolved contract (e.g. R22 → H-02's
    logger-walk test; R14 → F-03's cancellation-safe hand-off tests);
  - the deferred list, which the release notes (J-04) quote: RedisHashStorage + migration (D113), album aggregation
    (D116), abi3 wheels (08 §4), and anything else dropped during implementation.
- **Registry completeness:** every breaking change and every `removal-4.0` item has a registry entry with a checker id
  or a manual-checklist item. The check is scripted against `aiogram/_migration/registry.toml`.
- **Story exit gates:** C-25, D-16, E-21, F-16, H-20, I-22, B-13 (go), A's oracle/benchmarks, 3x-24 (baseline release
  cut). Each is `done`, with the evidence linked.

**Out:**
- Fixing gaps (each gap gets a plan or a PR in the owning story).
- Beta feedback (J-03).

## Checklist

- [ ] Script `scripts/ga_inventory.py`: parse every plan's header table (Decisions, Status), list D/PD ids without a
      plan, and emit `inventory.md` skeleton rows.
- [ ] Fill the manual columns (PR link, test evidence). An evidence cell must name a test path or an acceptance
      criterion that ran in CI.
- [ ] P1 table: 21 rows, each with test evidence or a linked blocking issue.
- [ ] Registry completeness check (scripted). A failing row becomes a blocking issue.
- [ ] Verify the owner-flagged "Decide" items across all plans (Notes sections) have recorded owner answers. List the
      open ones as GA blockers or explicitly accepted defaults.
- [ ] Confirm uk_UA is recorded as not GA-blocking (I-11 proposed default) or overridden by the owner.
- [ ] Tests for the inventory script (100% coverage).
- [ ] No changelog fragment (internal).

## Acceptance criteria

- `inventory.md` has no row with an empty evidence cell, except rows marked "deferred / withdrawn" with a decision id.
- All 21 P1 rows carry test evidence.
- The registry check reports zero missing entries.
- Every story exit gate is `done` with evidence.
