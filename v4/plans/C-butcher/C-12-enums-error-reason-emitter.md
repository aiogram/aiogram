## Motivation

- `aiogram/enums/*.py` (39 modules on 3.x) are generated by legacy butcher through libcst, and `ContentType` is removed
  in 4.0 (11 §1).
- D47 adds a generated `ErrorReason` `StrEnum` from `errors.json`, exposed as `e.reason`. PD-24: member names are
  **pinned in the overlay after first emission**, and `butcher diff` reports renames, so a Telegram rewording never
  silently renames a member.

## Scope

**In:**
- `crates/butcher/src/emit/enums.rs`: one `aiogram/enums/<snake>.py` per IR enum as a `StrEnum` (`IntEnum` where the
  values are ints, if any), plus aiogram-only enums from the overlay (`UpdateType`, from the `extract` rule over
  `Update` fields). `aiogram/enums/__init__.py` exports. Imports computed from the IR, `ruff format` applied.
  `ContentType` is not emitted.
- `crates/butcher/src/emit/error_reason.rs`: `aiogram/enums/error_reason.py` with:
  - members named from the MTProto code where one exists (`ADMINS_TOO_MUCH`), otherwise from a normalised slug of the
    message, and overridden by `errors.toml` pins and stable names (`MESSAGE_NOT_MODIFIED`, `BOT_BLOCKED`);
  - a `_TEMPLATES` table: anchored regex → member, with placeholder names;
  - `match_reason(description: str) -> tuple[ErrorReason | None, tuple[str, ...]]`: exact lookup first, then the
    template regexes in order. D-02 makes the lookup lazy (on first `e.reason` access).
- **Pinning:** after emission, `build --pin-errors` writes every member name into `butcher/overlay/errors.toml`.
  Afterwards a message whose computed slug changes but whose pin exists keeps the pinned name. A pinned message that
  disappears upstream is reported by `diff`, and the member is kept as deprecated through the ledger window
  (`removed_entity` with `entity = "ErrorReason.<NAME>"`).

**Out:** exception wiring (`e.reason`, `e.reason_args`) and the `RestartingTelegram` removal (D-02); error filters (E-11).

## Acceptance criteria

- `python -c "from aiogram.enums import ChatType, UpdateType, ErrorReason"` works on a dev build. `from aiogram.enums import ContentType` raises `ImportError`.
- For each of the 945 messages (live-gated) or the fixture set (always), `match_reason(msg)[0]` is the expected member, and template captures equal the placeholders.
- With a pinned `errors.toml`, rewording one fixture message keeps the member name, and `diff` reports "message text changed, name pinned".
- Two runs emit byte-identical files.
