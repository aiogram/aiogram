## Motivation

672 of 719 docs pages are API reference pages generated by legacy butcher's 6 Jinja templates. In 4.0 the reference
itself is sphinx-autoapi over the generated `.pyi` stubs (D79, R29). butcher emits only thin index and entity pages that
show the short import first, reversing today's order where `docs/api/methods/*.rst` shows the deep path first (D16).

## Scope

**In:** `crates/butcher/src/emit/rst.rs` with minijinja templates ported from `.butcher/templates/**` →
`docs/api/{types,methods,enums}/index.rst` and per-entity pages. Each page has the title, a one-line summary, the
import block (`from aiogram.types import X` first, deep path as a footnote), and an autoapi directive pointing at the
stub. Sections follow the IR categories. Ledger-deprecated entities are marked. English only (D81).

**Out:** the docs build, autoapi config, Diátaxis restructure (I-09, I-10); uk_UA (I-11).

## Checklist

- [ ] Port the 6 templates to minijinja (Jinja-compatible).
- [ ] Short-import-first block.
- [ ] Remove the legacy-generated pages that the new set replaces (same paths where possible, so external links survive).
- [ ] Test: every IR type, method and enum has exactly one page, and no page exists for a removed entity.
- [ ] Tests (100% coverage of new code)

## Acceptance criteria

- The docs build (I-09's import-free command; until it lands, `uv run --group docs bash -c 'cd docs && make html'`, since `docs` is a dependency group per D68) succeeds with no "document isn't included in any toctree" warnings for the API section.
- The page paths for unchanged entities match 3.x paths.
- Two runs emit byte-identical files.

## Rejected alternatives

| Alternative | Why rejected | Decision |
|---|---|---|
| Full per-entity RST with field tables (legacy) | autoapi on stubs is the reference | D79 |
| Standard autodoc | Imports modules, which needs the compiled extension | R29 |
| Translating the generated reference | Changes every bump; narrative only | D81 |
