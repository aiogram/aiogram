# Pinned corpus

Fixed inputs for the benchmarks and the differential oracles, so that every measurement and every
comparison runs on the same bytes. Dev tooling: `benchmarks/` is not shipped in the sdist or wheel.
`tests/test_corpus_manifest.py` checks the manifest in CI.

```
MANIFEST.toml   one [[input]] per id
wire/           Telegram payloads: updates, response envelopes, keyboards, text + entities
routing/        declarative router topologies plus the events to feed them
requests/       Bot API method calls
files/          small binary fixtures referenced by requests
utils/          inputs for utilities that have no wire form (callback data classes)
traces/         recorded + redacted real traffic (benchmarks/record/)
entities/       entity layout reference corpus (3x-17)
```

Ids are stable and cited by plans and bench cases. **Inputs are append-only** once a baseline is
recorded on them: never edit a pinned file, add a new id instead.

## `MANIFEST.toml`

```toml
schema = 1

[[input]]
id = "update.realistic"               # stable id, also the file stem
kind = "update"                       # update | response | routing | request | file | keyboard
                                      # | entities | callback_data | trace | case
path = "wire/update.realistic.json"   # relative to this directory; omitted for kind = "case"
sha256 = "…"                          # of the file's bytes; omitted for kind = "case"
on_3x = "ok"                          # update / response only, see below
method = "sendMessage"                # response only: the method the envelope answers
status = 200                          # response only: the HTTP status it comes with
uses = ["request.sendMessage.defaults"]  # case only (optional): ids the case reads
provenance = { source = "hand", date = "2026-11-18", aiogram = "3.32.0", bot_api = "10.4", author = "…" }
notes = "…"
```

- `provenance.source`: `hand` (curated by hand), `synthesised` (generated by a rule, described in
  `notes`) or `recorded` (a real trace, always redacted; `notes` says "recorded + redacted").
- `on_3x`: what the current 3.x does with the input, kept true by the test: `ok`, or the exception
  class name. Updates go through `Update.model_validate_json` and then `Update.event_type`;
  responses through `BaseSession.check_response` with `method` and `status`. A change that makes
  3.x accept or reject an input updates this field in the same PR.
- `kind = "case"` is a bench/oracle case that needs no data file (or only reads `uses`).

Wire files are compact JSON as Telegram sends it. Timestamps are fixed; user, chat and file ids
are fabricated.

## `routing/*.toml`

A topology that a 3.x adapter (A-10) and a 4.0 adapter can both build, so it names behaviour, not
3.x API calls.

```toml
schema = 1

[variants]
fsm = ["on", "off"]          # run the topology with FSM storage on and off

[[router]]
name = "dp"                  # the first router is the root (the dispatcher)
outer_middlewares = [{ event = "message", kind = "pass" }]
inner_middlewares = [{ event = "message", kind = "pass" }]

[[router.handler]]           # handlers of the router above, in registration order
id = "h0"
event = "message"
filters = [{ kind = "command", commands = ["c0"] }]   # all must pass

[[router]]
name = "r1"
parent = "dp"                # included into that router, in file order

[[event]]                    # fed in order
name = "first"
update = "update.text.small" # a wire id of kind "update"
patch = { "message.text" = "/c0" }   # dotted path -> value, applied to a copy of the payload
expect = "h0"                # handler id, or "unhandled"
```

Filter kinds: `command` (`commands`: names without the slash), `text_eq` (`value`: message text
equals it). Middleware kinds: `pass` (calls the next handler, does nothing else). New kinds are
added here first, with the plan that needs them.

## `requests/*.toml`

```toml
schema = 1
method = "sendMediaGroup"    # Bot API method name

[params]                     # Bot API params, as in the method's documentation
chat_id = 100000001
media = [{ type = "photo", media = { corpus_file = "red.png" } }]   # an upload: a file in files/

[defaults]                   # optional: bot-level defaults (DefaultBotProperties field names)
parse_mode = "HTML"

[extra]                      # optional: params outside the pinned schema, sent as given
future_param = "x"
```

## `utils/callback_data.*.toml`

```toml
schema = 1
separator = ":"
data = "p20:42:approve"      # the callback data to filter

[[classes]]                  # CallbackData classes, in filter order
prefix = "p0"
fields = [{ name = "id", type = "int" }, { name = "action", type = "str" }]
```

## Recorded traces

`traces/<id>.jsonl` (kind `trace`): the first line is `{"provenance": {…}}`, each other line one
request as written by `benchmarks/record/recorder.py` (`method`, `params`, `files`, `status`,
`response`). Only redacted traces are committed; see `benchmarks/record/`.
